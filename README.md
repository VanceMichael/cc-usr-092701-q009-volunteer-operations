# 国际赛事志愿服务排班后台

面向第48届世界技能大赛闭幕周的志愿服务管理后台：统一管理报名、语言与岗位资质、
班次、签到、替班、服务对象、培训和表彰，并根据休息间隔与岗位要求给出**可解释**的
排班结果。数据均为演示用虚构内容，仅依赖 Python 3.11+ 标准库。

## 参与方与权限

| 角色 | 能力边界 |
| --- | --- |
| 赛事服务中心 `staff` | 资质/语言/证件核验、培训登记、开班、复核结论、封存签到、表彰 |
| 组委会调度员 `committee` | 可**跨高校**调度派班、审批替班；**不能**修改已封存签到，也不做核验 |
| 高校管理员 `school` | 只能查看/操作**本校**志愿者的数据与替班 |
| 志愿者 `volunteer` | 只能看自己的画像、为自己签到或发起复核/替班申请 |

## 关键业务规则

- **可解释排班** `Service.evaluate`：逐条输出 `matched`（培训、已核验证件、
  已核验语言、可补小语种缺口）与 `reasons`（时间重叠、休息间隔不足、缺培训、
  敏感岗位证件/语言未核验、小语种缺口无法覆盖、名额已满）；连续清晨出勤只给
  `warnings` 不阻断。`suggest` 按合格优先排序给出候选。
- **敏感岗位**（机场抵离、涉外采访）只承认 `verified=True` 的证件与语言能力；
  自报未核验的小语种不能上岗。
- **一人不得重叠班次**，相邻班次须满足岗位 `min_rest_hours` 休息间隔。
- **替班链**：派班永久保留 `original_volunteer_id` / `original_authorized_by`，
  审批通过后只更新当前责任人；每次申请按 `seq` 成链，替班人重新做资格核验并把
  结论快照 `eligibility` 随审批留档。已封存签到的派班禁止替班。
- **签到与复核**：超过宽限期记迟到；班后扫描未签到自动登记「漏签复核」；
  漏签、迟到申诉、补录都进入复核队列，**只有服务中心作出结论后**才回写出勤与
  时长，不会直接改写记录。
- **封存**：封存后任何角色（含组委会）都不能补刷、替班或再发起复核；尚有未结
  复核的签到暂不封存。
- **时长台账与表彰**：台账按有效出勤重建，时长计入**实际服务人**，替班/补认/
  驳回自动同步；表彰记录累计分钟数、逐条台账依据和理由，重算时旧结果置
  `superseded`。
- **重启恢复**：所有写操作即时落盘（原子替换）；持久化任务（岗前提醒、漏签扫描、
  表彰计算）在重启时把中断在 `running` 的任务退回 `pending` 继续推进，已完成
  任务不重复执行、不重复发通知。
- **一人一档** `Service.profile`：真实班次（原责任人/当前责任人角色）、完整
  替班链、签到状态、累计时长台账与最新表彰依据。

## 代码结构

```
src/volunteer_operations/
  models.py    领域对象（档案/岗位/班次/派班/替班/签到/复核/台账/表彰/任务）
  timeutil.py  ISO8601 时间、重叠与休息间隔计算
  store.py     JSON 原子持久化、角色与数据可见性边界
  service.py   全部业务用例与可解释排班
  context.py   领域资料读取校验（既有）
  demo.py      闭幕周端到端场景演示
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

## 编译检查

```bash
python3 -m compileall -q src tests
```

## 命令行

```bash
# 既有领域资料摘要
python3 -m src.volunteer_operations.context fixtures/context.json

# 闭幕周端到端演示（打印一名志愿者的真实班次、替班链、累计时长与奖励依据）
python3 -m src.volunteer_operations.demo
# 或指定持久化文件，重启后未完成的提醒/漏签扫描/表彰仍会继续推进
python3 -m src.volunteer_operations.demo /tmp/volunteer-state.json
```
